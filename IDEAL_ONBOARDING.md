# SEO Audit Engine — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md` §9 (приложения без классического
`connect_*` к внешнему сервису). Целевой пользователь: SEO-специалист/агентство,
которому нужен технический аудит своих/клиентских сайтов (18+ проверок).

## 1. "Credential type" — на самом деле его нет
Нет отдельного `connect_*`. Первое реальное действие пользователя — `audit_sites`
(указать один или несколько URL) или подтягивание уже подключённых сайтов из
Sites Registry/WordPress Hub через `list_connected_sites`.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty`, НО не с призывом "подключить аккаунт" (его нет), а с
   прямой формой "Введите URL сайта(ов) для аудита" — CTA сразу actionable, без
   промежуточного OAuth-шага, которого структурно не существует.
2. **Cross-app awareness** — если уже есть сайты в Sites Registry/WordPress Hub —
   идеально: список для быстрого выбора вместо ручного ввода URL с нуля.
3. **Во время аудита** — идеально: живой прогресс "Проверено N из M страниц" + список
   уже найденных находок по мере поступления (не единый спиннер до конца всего аудита,
   который может занять минуты на больших сайтах).
4. **После завершения** — сводный отчёт по здоровью сайта(ов) + план задач по
   критичности — сразу, максимально actionable.
5. **Прерванный аудит** — `resume_audit` уже есть — идеально: явный баннер "Аудит был
   прерван — продолжить с места остановки?" при повторном открытии, не тихая потеря
   прогресса.
6. **Расписание** — `set_schedule` — идеально: явное предложение настроить
   автоматический периодический аудит СРАЗУ после первого ручного запуска, пока
   ценность свежа в памяти пользователя.
